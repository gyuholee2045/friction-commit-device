friction-commit-device의 **UX 트랙** 산출물. 두 버전을 따로 관리한다.

### 히어로 2단 상태 (index.html)
- **부유(기본):** 중앙에 크게 기울어져 표류. 중앙 라벨과 스텝바는 숨김, 홀드 안내는 **하단 문구 영역**에 표시.
- **착지:** 커서가 화면 중앙 근처(정규화 반경 0.40, 이탈 0.58 히스테리시스)에 들어오면 작업 사이즈로 이동. 중앙 라벨·스텝바 등장, 하단은 본래 문구로 복귀.
- 전환은 등속 이동 + smoothstep 이라 **오버슈트가 구조적으로 불가능**하다(바운스 금지 요구). 홀드 중에는 착지 상태로 잠가 손 밑에서 링이 달아나지 않게 한다.

## 여는 법
- 로컬 서버(권장): 프로젝트 루트에서 `.claude/launch.json`의 `web-prototype` 기동 → `http://localhost:3000/` (index) · `http://localhost:3000/compare.html`
- 또는 파일을 브라우저로 직접 열기 (file://). CDN(three.js) 로드를 위해 인터넷 필요.

## 기술
**index.html: Three.js r180** · 그 외(compare.html, 체크포인트들): r165 — importmap, jsdelivr CDN.
MeshPhysicalMaterial transmission · EffectComposer 포스트프로세싱 · 정점 셰이더.
**배경은 따뜻한 중립 아이보리(`#f1efe9`)** — 물의 감쇠색이 차가운 아쿠아라, 배경까지 차가우면 외곽 유리 껍질이 배경에 묻혀 실루엣이 안 읽힌다. 색온도로 분리한다.
링은 커서에 반응한다(`uPtr`/`uTouch`): 커서가 물 띠 근처에 오면 그 지점에 파문이 인다.

### index.html 링이 r180 을 쓰는 이유 (내리지 말 것)
- `dispersion` 은 **r167+**, `transmissionResolutionScale` 은 **r173+** 에서만 존재. r165 에 적어둔 `dispersion` 값은 조용히 무시됐었다.
- 물결이 조명에 반응하려면 정점을 미는 것만으로 부족하다. `surf(u,v)` 를 파라메트릭 곡면으로 두고 유한차분으로 **노멀을 재계산**한다 — 이걸 빼면 표면은 출렁이는데 셰이딩은 매끈한, 고무 같은 링이 된다.
- 튜브 반지름(`tubeAt`)이 링을 따라 부풀고 가늘어져야 유체로 읽힌다. 고정 반지름이면 "파이프에 물결 텍스처를 씌운" 형상이 된다.
- EffectComposer 사용 시 **OutputPass** 가 마지막에 있어야 톤매핑·색공간이 한 번만 정확히 적용된다.
- **링 위를 도는 패턴은 강체 회전으로 읽힌다.** 노이즈 위상을 `u ± uTime` 으로 이동시키면 물결이 흐르는 게 아니라 링이 의미 없이 반시계로 도는 것처럼 보인다. 위상은 노이즈 볼륨의 3번째 축으로 진행시켜 **제자리에서 끓게** 할 것. 튜브 단면 방향(v)으로 도는 것도 같은 이유로 두 겹을 반대로 굴려 상쇄한다.
- 자갈 같은 젖은 질감은 **v(단면 방향) 변화**에서 나온다. 그 패싯이 안쪽 컬러 유체를 렌즈처럼 쪼갠다. 이걸 없애면 한 스케일짜리 매끈한 덩어리만 남아 플라스틱처럼 보인다.
- 미세 레이어(`P*16.5`)는 정점이 받쳐줘야 산다. 토러스 세그먼트를 줄이면 샘플링에 걸려 조용히 사라진다 (현재 96×512, 107fps).
- **`v`(단면각)를 노이즈 좌표에 그대로 넣지 말 것.** `v` 는 `atan()` 산출이라 ±π 에서 감기고, 그 지점에서 좌표가 ~9단위 점프해 변위와 유한차분 노멀에 불연속이 생긴다 → 튜브 안쪽 적도를 따라 날카로운 크리즈. `tnc(u,v,ru,rv)` 로 (u,v)를 **양쪽 모두 주기적인** 3D 좌표로 매핑해서 쓴다.
- **`clock.getElapsedTime()` 뒤에 `clock.getDelta()` 를 부르지 말 것.** getElapsedTime() 이 내부에서 getDelta() 를 호출해 델타를 소비하므로, 뒤이은 getDelta() 는 **정확히 0** 을 돌려준다. 이 순서 때문에 dt 가 항상 0 이었고 — 커밋 버스트 입자가 한 번도 안 움직였고, `rippleT+=dt` 가 멈춰 커밋 물결이 영구히 켜진 채 uTime=0 에 고정됐다. 순서를 **getDelta() 먼저, elapsed 는 `clock.elapsedTime`** 으로 읽는다. (런타임 검증: 기존 순서 delta=0 / 수정 순서 delta=0.125)
- **프레임당 상수 이동은 쓰지 말 것.** 전환 속도가 화면 주사율에 종속된다(144Hz 와 60Hz 가 다르게 동작). 초당 비율 × dt 로 쓴다.
- **`opacity` 로 투과(transmission) 재질을 페이드 아웃할 수 없다.** 투과된 배경이 그대로 합성돼서 아무리 낮춰도 형체가 남는다. 사라지게 하려면 **scale** 로 없애거나 `visible=false` 로 꺼야 한다.
- **중앙 마스크(`.cmask`)는 지우지 말 것.** 가운데 "돼지코"(초승달 한 쌍)는 확산 연출이 만드는 게 아니라 **투과성 토러스가 배경을 자기 축으로 모으는 고유 현상**이다. 확산 축소·Z 평탄화 제거·transmission 감쇠·수축 소멸 네 가지를 모두 시도했지만 남는다. 대신 마스크를 `fillV` 에 연동해 **부유·호버 중에는 완전 투명**, 채움 45% 이후에만 나타나게 해뒀다.
- **환경 룸을 새까맣게 두지 말 것.** 오목한 물결면이 그 어둠을 한 점에 모아 매끈한 검은 타원처럼 렌더된다. 룸 바닥을 `#39404f` 로 띄웠고, 대비는 소프트박스 스트립이 담당한다. (검증: 어두운 픽셀 프레임 2/25 → 0/25)

## 메모
- 투과 유리 안의 내부 컬러 유체는 반드시 **불투명**이라야 비춰짐 (transparent면 안 보임) — 페이드는 scale로.
- 같은 이유로 **투과 재질 기포를 물 안에 넣지 말 것.** three 는 굴절 버퍼를 불투명 지오메트리로만 만들어서, 물 안의 투과 기포는 샘플할 게 없어 검은 얼룩으로 렌더된다. (기포 자체는 산만해서 현재 제거된 상태.)
- index.html 과 compare.html 은 **더 이상 같은 3D 코어가 아니다.** index 는 r180 하이브리드 링, compare 는 r165 구코어. 한쪽 수정이 다른 쪽에 자동 반영되지 않음(별도 파일).
